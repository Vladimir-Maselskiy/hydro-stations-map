# Гідро — карта станцій рівня води

Готовий інтерфейс тестового завдання на Vue 3: інтерактивна карта України, пошук станцій та річок, обрані, графік і таблиця останніх вимірювань. Мова інтерфейсу — українська.

## Запуск

Потрібні Node.js 20.19+ у гілці 20 або 22.12+ та npm.

```powershell
cd frontend
npm ci
npm run dev
```

Відкрити http://127.0.0.1:5173/. Swagger: http://127.0.0.1:5173/docs/.
API запускається разом із Vite. Окремий бекенд та ключі не потрібні.

## Перевірка

```powershell
cd frontend
npm test
npm run build
```

13 тестів: контракт API, пагінація, фільтри, ізоляція вимірювань станції, інтеграція Vite/Swagger, повторення 503, скасування повторних запитів, геометрія графіка для однакових значень і порядок дат. Збірка перевірена. У браузері перевірені карта, вибір станції, деталі, пошук «Пост 00123», збереження обраних і мобільна ширина 390 px без горизонтального переповнення.

## Як користуватися

- Переміщення або масштабування карти оновлює станції в її межах. Кнопка ⌖ повертає до всього регіону.
- Пошук працює за назвою станції або річки у всьому наборі, незалежно від карти. Наприклад, «Пост 00123» або «Десна». Пошук за містом не підтримується наданим API.
- Завантажуються сторінки по 100 станцій. Кнопка «Показати ще» додає наступну сторінку одночасно до списку і карти. Повідомлення на карті пояснює, якщо показані не всі результати. Наближення карти звужує вибірку.
- Клік на точку або рядок відкриває останній рівень, зміну до попереднього виміру, графік та історію за 7, 14 або 36 днів. Точне значення точки графіка доступне при наведенні; усі значення також є в таблиці.
- Зірочка зберігає станцію у браузері. Вкладка «Обрані» показує збережені станції з усіх областей; пошуковий рядок фільтрує і їх.
- На телефоні карта і список перемикаються вкладками, деталі відкриваються окремою панеллю. Панель закривається кнопкою, Escape або натисканням на тло.

## Ключові рішення та припущення

- Vue 3 Composition API без глобального сховища: для одного робочого екрана достатньо реактивного локального стану. Leaflet відповідає за карту; графік реалізований SVG без додаткової бібліотеки. `src/api.js` містить повторні запити та чисту функцію побудови графіка.
- Пошук має затримку 350 мс, переміщення карти — 300 мс. Попередні запити скасовуються через AbortController. Відповіді старої станції не можуть замінити нову історію.
- HTTP 503 повторюється до трьох загальних спроб із затримками 350/700 мс. Інші HTTP-помилки не повторюються автоматично. Після помилки можна повторити запит вручну; помилка наступної сторінки не стирає вже отриманий список.
- Дані синтетичні й датовані січнем 2026; інтерфейс показує фактичну дату, не називає їх поточними. Час відображається в Europe/Kyiv. Зміна — різниця між сусідніми вимірами в метрах.
- Порогів небезпеки та нуля поста немає у контракті. Кольори маркерів позначають лише вибір станції, а не безпеку рівня води.
- Доступність: підписи полів та кнопок, видимий фокус, клавіатурний вибір маркерів, таблиця як текстова альтернатива графіку, Escape, обмеження Tab усередині діалогу, повернення фокуса, підтримка reduced motion.

## Відомі обмеження

- Фонові тайли OpenStreetMap та шрифт Google Fonts потребують інтернету. Є системний запасний шрифт; при помилці тайлів показується повідомлення, а API, список і точки продовжують працювати. Масові завантаження тайлів не виконуються.
- На великій області спочатку видно лише перші 100 станцій: це свідоме обмеження кількості запитів і маркерів. Повний набір доступний через пагінацію або звуження карти/пошуку; кластеризацію всіх 10 000 точок не реалізовано.
- Обрані локальні для браузера, без акаунта та синхронізації. Якщо сховище браузера заборонено, вони доступні до перезавантаження.
- API входить лише до dev-сервера. `npm run build` перевіряє збірку frontend; `npm run preview` не запускає API. Для оцінювання використовувати `npm run dev`. Для Vercel додано окремі Functions і команду build:vercel (див. нижче); звичайна локальна збірка не змінюється.

## Інструменти та робота

Реалізація підготовлена за допомогою Codex: аналіз OpenAPI і стартового коду, Vue/Leaflet/SVG, автоматичні node:test перевірки, production-збірка та перевірка у Chrome на desktop і mobile. Початковий API і його тести збережені. Зовнішні дані для станцій не використовуються.

## Вміст

- `frontend/src/` — інтерфейс та API-клієнт.
- `frontend/client.test.js` — додані клієнтські тести.
- `frontend/api-middleware.js` — наданий локальний API.

ZIP для здачі не містить node_modules, dist, кешів або Git-метаданих. Після розпакування виконати інструкцію запуску вище.

## Окремий режим деплою на Vercel

Локальний режим тестового збережений: команди `npm ci`, `npm run dev`, `npm test` і `npm run build` виконуються у `frontend/` як раніше. Локальний API та його тести не змінювалися.

Для Vercel додані окремі файли:

- `vercel.json` — налаштування встановлення, збірки та маршруту `/health`.
- `api/stations.js`, `api/stations/[station_id]/measurements.js`, `api/health.js` — Node.js Vercel Functions.
- `deployment/handler.js` — адаптер наданого middleware для серверних функцій. Дані, пошук, пагінація, валідація та випадкові 503 залишаються однаковими в обох режимах. Для відповідей API встановлено `Cache-Control: no-store`.
- `deployment/prepare-static.mjs` — додає Swagger та OpenAPI до результату Vercel-збірки, без зовнішнього CDN для документації.

### Налаштування у Vercel

1. Завантажити репозиторій у GitHub/GitLab/Bitbucket та імпортувати у Vercel.
2. **Root Directory: корінь репозиторію**, де лежить `vercel.json`, НЕ `frontend`.
3. Framework Preset: **Other**. Node.js: **22.x або 24.x**.
4. Команди беруться з `vercel.json` автоматично: Install — `npm ci --prefix frontend`; Build — `npm run build:vercel`; Output — `frontend/dist`.
5. Натиснути Deploy. API-ключі, база даних та environment variables не потрібні.

У результаті `/` відкриває застосунок, `/api/stations` та `/api/stations/{id}/measurements` працюють у Functions, `/health` перевіряє API, `/docs/` відкриває Swagger. Відносні URL frontend не змінюються; CORS не потрібний, бо сайт та API мають один домен.

### Локальна перевірка режиму Vercel

З кореня репозиторію, після `npm ci --prefix frontend`:

```powershell
npm run test:vercel
npm run build:vercel
```

Три додаткові тести перевіряють експорти серверних обробників, фільтри/пагінацію/історію та доступність health і документації при суцільних 503. Вони запускають ті самі Node-обробники через HTTP. Саму платформу Vercel ці тести не емулюють.

Звичайний статичний preview результату `build:vercel` не запускає Functions. Для перевірки маршрутизації платформи використовуйте Vercel Preview Deployment або `vercel dev` із Vercel CLI. Публікацію з цього робочого середовища не виконано; конфігурація та серверні обробники перевірені локально.
